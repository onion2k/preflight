Accessibility — WCAG 2.2 AA

02

Pick the standard explicitly and write it down. WCAG 2.2 Level AA is the usual commitment and what most procurement and legislation (EN 301 549, ADA Title II, the European Accessibility Act) actually reference. Automated tools catch roughly a third of issues; the rest is the manual list below.

Security headers and hardening

03

Set these at the edge (host config, CDN, or netlify.toml/_headers) rather than in markup — several of them are ignored when they arrive in a <meta> tag. Verify against the live response, not the config file.

Files crawlers and agents look for

04

All served from the domain root with the right content type. Request each one from the production URL — a redirect or an HTML 404 body counts as broken.

FileWhy it matters
/robots.txtMust not still say Disallow: / from staging. Point it at your sitemap. Decide, deliberately, which AI crawlers you allow.
/sitemap.xmlCanonical URLs only, no redirects or noindexed pages, correct lastmod. Split by index file above 50k URLs.
/llms.txtA Markdown map of the site for language models: what it is, and links to the pages worth reading. Optional, cheap, increasingly expected.
/.well-known/security.txtHow to report a vulnerability, with an Expires field. Prevents researchers guessing at your Twitter DMs.
/favicon.icoPlus SVG icon, apple-touch-icon and a web manifest with the right theme colours if you want an installable app.
/humans.txtCredit the people who built it. Entirely optional, still nice.
/ads.txtOnly if you sell advertising. Wrong or stale entries cost revenue.
/feed.xmlRSS or Atom if you publish anything serially. Validate it, and link it from <head>.

Performance and Lighthouse

05

Run against the production build on a throttled mobile profile, three times, and take the median — a single local run flatters you. Set a target and treat it as a gate, not a score to admire.

Error and edge-case pages

06

Each needs the correct status code as well as a designed page. A pretty 404 served with a 200 pollutes search indexes and hides broken links from every tool you own.

StatusNeeds
404Site navigation, search, and a link home. Must return 404. Test a deep nonsense URL, not just /404.
500A static page that renders when the app is down — no database, no API, no build step.
403 / 401If anything is gated: explain whether to sign in, request access, or give up.
410For content deliberately removed, so crawlers drop it instead of retrying.
503Maintenance page with Retry-After, used during planned downtime.
OfflineIf you register a service worker — and check the worker's update path before launch, not after.

Two failures worth checking twice

The first is robots.txt carrying a staging Disallow: / into production — invisible on the site itself, and it costs weeks of indexing. The second is a 404 page that returns HTTP 200, which quietly disables every broken-link tool you own and fills search results with a page saying nothing was found. Both take ten seconds with curl.
